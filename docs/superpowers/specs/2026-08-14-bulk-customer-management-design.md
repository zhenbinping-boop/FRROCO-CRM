# 客户批量管理设计

## 目标

在客户管理列表中支持对多个客户执行批量修改和批量删除，同时复用现有客户权限和数据范围校验，不引入数据库表、迁移或 RLS 变更。

第一版批量修改字段限定为：客户等级、客户阶段、客户来源、备注。门店、销售、设计师等归属字段继续使用现有交接流程，不纳入普通批量修改。

## 用户流程

客户卡片增加复选框。用户可以逐条选择客户，也可以选择当前筛选结果；选择数量最多 100 条。选择至少一条后，在列表上方显示批量操作栏，包含批量修改、批量删除和清空选择。

批量修改打开弹窗。每个字段都有独立的启用开关，只有启用的字段会被提交；启用备注并留空表示清空备注，未启用的字段保持原值。提交成功后刷新客户列表并清空选择。

批量删除需要二次确认，明确显示选中数量和“已有订单或回款记录的客户不会被删除”。删除完成后显示成功数量和失败原因，并刷新列表、清空选择。

客户列表刷新期间保留统一工作台壳，但不保留已提交操作的旧选择状态，避免对已删除或已更新的卡片继续操作。

## 后端接口

新增两个接口，路由定义必须放在 `/customers/:id` 之前：

### `PATCH /customers/batch`

请求体：

```json
{
  "ids": ["customer-id-1", "customer-id-2"],
  "changes": {
    "tier": "A",
    "stage": "FOLLOWING",
    "customerSource": "老客转介绍",
    "notes": "统一补充的备注"
  }
}
```

`ids` 至少 1 个、最多 100 个且不能重复。`changes` 至少包含一个允许修改的字段。字段值沿用现有客户校验规则。

服务端使用 `AND` 同时组合 `customerAccessWhere(request)` 和 `id in ids`，不能把 ID 条件和数据范围条件合并到同一个可覆盖权限的 `OR` 中。选中客户中只要有一条已删除、不可见或超出当前数据范围，整个修改操作拒绝并返回“客户列表已变化，请刷新后重试”，不泄露额外记录信息。

### `POST /customers/batch-delete`

请求体：

```json
{
  "ids": ["customer-id-1", "customer-id-2"]
}
```

同样限制 1 到 100 个不重复 ID，并使用数据范围和 ID 的 `AND` 条件确认所有选中客户仍可操作。客户不存在或不可见时拒绝整个请求。

对可见客户执行统一预检：存在订单或回款关联的客户进入失败明细，其余客户在同一个 Prisma transaction 中删除。接口返回请求数、成功删除数和失败明细，不因单个受保护客户阻止其他可删除客户完成操作。

示例响应：

```json
{
  "data": {
    "requested": 3,
    "deleted": 2,
    "failed": [
      { "id": "customer-id-3", "code": "CUSTOMER_HAS_ORDERS", "message": "该客户已有订单或回款记录，不能直接删除" }
    ]
  }
}
```

## 权限与安全

- 批量修改要求 `customer.update`。
- 批量删除要求 `customer.delete`。
- 不接受门店、代理商、销售或设计师归属字段；这些字段仍要求 `customer.transfer` 的单客户交接接口。
- 批量更新销售或设计师的能力不在本次范围内，因此不扩展 `assertUserAssignmentAccess` 的批量语义。
- 客户 ID 只能作为候选集合，服务端始终重新应用当前用户的数据范围。
- 不新增服务端特权查询，不绕过现有 Express 鉴权、Prisma 数据范围和 PostgreSQL RLS 防线。

## 前端结构

- `api-pages.js` 为动态客户卡片增加 `data-customer-id`，并暴露列表刷新函数供批量操作完成后调用。
- 新增 `customer-bulk.js`，负责选择状态、批量操作栏、修改弹窗、删除确认和结果提示；通过事件委托兼容客户列表异步渲染及单页模块缓存。
- `customers.html` 提供批量操作栏挂载点和可访问名称；六个主模块页面中的客户页脚本顺序保持可重复执行。
- 批量操作不拦截客户详情链接，详情仍然保持独立 URL。
- 选中卡片使用稳定 ID，不依赖客户姓名、手机号或详情链接解析。

## 错误处理与一致性

- 未选择客户时，批量按钮不可用。
- 超过 100 条时阻止提交并提示缩小筛选范围。
- 更新遇到列表过期或权限变化时整体失败，提示刷新后重试。
- 删除允许“可删除成功、有关联订单失败”的部分结果，并逐条展示失败原因。
- 成功或部分成功后重新加载客户列表，重新生成筛选选项，并清空旧选中状态。
- 网络错误沿用现有 `FarockAPI` 错误提示；401 继续由现有会话失效流程处理。

## 测试策略

- 后端契约/策略测试覆盖：ID 上限和重复 ID、允许字段白名单、权限节点、数据范围 `AND` 组合、更新整体拒绝、删除订单保护和部分成功结果。
- 前端契约测试覆盖：卡片 ID、批量脚本入口、选择数量限制、详情链接不被拦截和刷新后清空选择。
- 对修改后的 JavaScript 执行 `node --check`，对后端执行 `npm run typecheck` 和现有用户策略检查。
- 在本地已登录浏览器验证：选择/全选、批量修改、批量删除、订单客户保护、筛选后刷新、模块切换返回后的选择状态。

## 明确不做

- 不新增审计日志表或数据库迁移；本次只返回当前操作结果。
- 不实现批量交接、批量修改组织归属、批量修改销售/设计师。
- 不把批量操作改造成异步任务队列；100 条上限以内使用一次请求完成。
