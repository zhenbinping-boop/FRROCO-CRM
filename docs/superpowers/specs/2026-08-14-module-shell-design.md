# FRROCO CRM 单页工作台壳设计

## 目标

主导航的六个模块在同一个工作台壳内切换，切换时不发生整页导航、不重复初始化公共布局和会话；客户详情、新建客户、交接和登记收款等操作页继续保留独立 URL。

## 方案

沿用现有静态 HTML 作为模块内容源，不引入前端框架或新的依赖。新增 `module-shell.js`：

1. 拦截六个主导航链接，使用 `history.pushState` 更新地址并通过 `fetch` 读取目标 HTML。
2. 从目标文档提取 `main` 和必要的对话框节点，替换当前内容节点；旧 `main` 通过 `replaceWith` 移除，清理旧模块的事件监听。
3. 复用现有 `layout.js` 的页面配置，更新标题、当前导航和操作栏。
4. 按模块加载已有页面脚本：客户模块加载导入、导出和 API 页面脚本；任务模块加载任务脚本；订单模块加载订单脚本；其他模块复用现有公共脚本。
5. 页面脚本加载失败时恢复上一个模块并显示错误提示；浏览器前进/后退通过 `popstate` 走相同切换流程。

## 数据与状态

`localStorage` 中的认证令牌、用户会话和现有 `FarockAPI` 保持不变。模块切换不会主动清空筛选条件或已加载的数据；已离开的模块 DOM 会被释放，返回模块时重新读取 HTML 和 API 数据，避免后台持有失效事件监听。后续若需要真正保留每个模块的筛选状态，可在当前路由器稳定后单独增加模块状态缓存。

## 错误与回归边界

- 未登录和管理员限制继续由现有页面入口及 `layout.js` 处理。
- 详情、表单和收款操作页不纳入单页内容切换，原有跳转行为保持不变。
- API 错误由原模块脚本显示；HTML 或脚本加载失败由工作台提示并保留当前内容。
- 不执行数据库、迁移或 RLS 变更。

## 验收

- 主导航点击不触发 `location.href` 或整页 `load`。
- 地址栏、刷新、前进/后退仍对应正确模块。
- 客户、任务、订单模块的现有数据加载脚本仍可执行。
- 未登录跳转、详情页跳转、创建/登记等操作不回归。
